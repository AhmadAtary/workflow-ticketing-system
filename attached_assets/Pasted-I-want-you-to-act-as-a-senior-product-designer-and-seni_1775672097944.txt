I want you to act as a senior product designer and senior frontend engineer.

Build a complete, professional, production-ready frontend for a self-hosted dynamic workflow ticketing system.

Important:
This system is NOT multi-tenant SaaS.
Each company will install and host the system on its own server.
There will be one main admin per installation who controls the whole system.

Your task is to create the FULL frontend only.
Do not build backend logic now.
Do not use fake complex backend implementations.
Use clean mock data and realistic UI flows.
The frontend must be structured so it can later be connected to a real backend easily.

--------------------------------------------------
MAIN SYSTEM CONCEPT
--------------------------------------------------

This is a workflow-driven ticket/task management system.

The admin can:
- Create teams with any name
- Create users
- Define workflows
- Assign each workflow step to a team

Tasks should:
- Move through multiple steps in sequence
- Each step belongs to a team/department
- When one step is completed → move automatically to next step

The system should feel like:
- Jira
- Internal workflow engine
- Approval/process system

--------------------------------------------------
USER ROLES & DASHBOARDS
--------------------------------------------------

The system must support TWO roles:

1) Admin
2) Normal User (Employee)

Both roles MUST exist in the SAME codebase and SAME application.

DO NOT create separate apps.

----------------------
ADMIN DASHBOARD
----------------------

Admin has FULL control:

- Manage teams
- Manage users
- Create/edit workflows
- Manage workflow steps
- Manage all tasks
- View reports & analytics
- Manage email templates
- Access system settings

Admin UI:
- Full sidebar navigation
- All modules visible
- Advanced controls
- Complex dashboard

----------------------
USER DASHBOARD
----------------------

Normal users have LIMITED access:

They can:
- View assigned tasks
- Work on current step
- Complete steps
- Add comments
- View task details
- Receive notifications

They CANNOT:
- Manage workflows
- Manage teams
- Access settings
- Access reports
- Manage email templates

User UI:
- Clean & simple
- Task-focused
- Minimal navigation

----------------------
ROLE-BASED BEHAVIOR
----------------------

- After login → detect user role
- Redirect:
  - Admin → /admin/dashboard
  - User → /dashboard

- Use role-based routing
- Protect routes
- Hide unauthorized pages
